# 随机数打脸实验室 · 双色球概率实验室（V1）

> 任何策略，在没有通过盲测之前，都不准自称"有效"。

用真实开奖数据持续检验"选号策略是否真的比随机数强"的公开实验平台。**不做**号码预测工具，**只做**统计与算法科普实验。首页 `public/index.html` 明确声明：不提供售彩、代购、充值、返利等服务；彩票开奖是独立随机事件，历史数据不影响未来结果。

这是方案里 **V0.5 → V1** 的迭代：V0 把"回测引擎是否算对"这件最不能返工的事做扎实；V0.5 把"开发集成绩"和"盲测成绩"第一次严格分开；V1 在此基础上加了"我的策略"权重滑块，把"开发集/盲测集分离"从一张静态的表格变成用户可以亲手拖动、亲手体验"数据窥探是什么感觉"的交互——这是方案第五节第 6 条一直悬而未决的功能，因为在 V0/V0.5 里三个基线策略都没有可调参数，这次真正派上了用场。

## V1 这一版新做了什么

- **"我的策略"权重滑块**（方案第五节第6条，README 上一版排在"还没做的"第一条，这一版补上）：
  - 三个滑块：**热号倾向 / 冷号倾向 / 随机扰动**，对应打分公式 `score = hot×热号频率 + cold×冷号遗漏 + random×确定性噪声`。红球取分数最高的 6 个，蓝球取分数最高的 1 个——纯前端浏览器 JS 实时计算，不需要服务器、不需要联网。
  - 噪声项不是裸 `Math.random()`，而是「期号 + runId」做种子的伪随机数：同一组权重 + 同一份历史数据，永远得到同一组号码、同一个回测成绩，拖动滑块看到的变化只反映权重本身，不掺杂"手气"噪声。
  - **刻意拆成两个数字，互不干扰**：拖滑块时始终可见的是"历史回测成绩（开发集）"，明确标注"仅供娱乐，不作为策略有效性证据"；"盲测成绩"默认隐藏，要点按钮才揭晓，且**换一组权重后之前揭晓的盲测结果会自动作废**（必须重新点击），防止用户拿着上一组权重的盲测数字误当成当前权重的结果。
  - 用浏览器控制台 + Node 双端交叉验证过：同一组权重下，浏览器端算出的开发集/盲测集均命中数和 `node src/build.js` 里 `weightedStrategy` 走 `walkForwardBacktest` 算出来的数字完全一致（本版本验证组：热50/冷20/随机30 → 开发集 1.1074、盲测集 1.4333，两边分毫不差）。
  - 新增 `src/strategies.js` 里的 `weightedStrategy`，以及给浏览器用的等价实现 `src/my-strategy-client.js`（因为页面要求自包含、双击即可打开、不能用 Node 的 `require()`，这份是手写的无 CommonJS 版本，逻辑改动需要两边同步改）。
  - `report.json` 的 `monte_carlo` 里新增 `dev_distribution` / `blind_distribution`——把按固定期号切分出的开发集/盲测集蒙特卡洛随机分布也吐出来，供前端实时计算"跑赢随机分布"的分位数，口径和站内其它地方保持一致（盲测集分位数只用盲测区间内的独立随机模拟来算）。

## V0.5 已完成（原有内容，未改动）

- **训练/验证/盲测三段式数据分割**（README 上一版排在"还没做的"第一条，这一版补上）：
  - 分割边界是**写死的固定期号**（验证集起点 26045、盲测集起点 26075），不是"数据长度的百分比"——原因写在 `src/backtest.js` 的 `splitByPeriodBoundaries` 注释里：如果每次重跑都按"最近 20%"划盲测集，这个集合会随数据变长整体后移，名字叫盲测、实际只是一个滑动的"最近窗口"，起不到真正的封存作用。现在的做法是：这个版本发布之后，第 26075 期永远是盲测集起点，以后每新增一批数据，盲测集只会往后累积变长（从当前 30 期慢慢涨），而不会被重新计算。
  - 蒙特卡洛随机分布也按同样的固定边界切分（`monteCarloDistribution` 新增 `boundaries` 参数），保证盲测集的"跑赢随机分布"分位数是用**只包含盲测区间**的独立随机模拟算出来的，而不是套用整段历史的分布——避免口径不一致。
  - 首页新增"训练 / 验证 / 盲测：三段式分割"章节，用一张表把每个策略的开发集成绩和盲测集成绩并排展示，并明确写清楚："当前盲测集只有 30 期，样本量还很小，这只是账本翻开的第一页，不构成任何'有效'的结论。"
- **近10/30/100期短期表现**（方案第九节 V0.5 阶段"短期爆点数据"）：只给数字，不做置信区间和显著性判断，避免被误读成"策略突然变强/变弱"。

## V0 已完成（原有内容，未改动）

- 真实历史数据：`gudaoxuri/lottery_history`（GitHub 公开镜像），251 期（2025-01-12 ~ 2026-09-08）
- 正确的 Walk-Forward 滚动回测：修正了原方案中"预测目标该用 `history[t]` 而不是 `history[t+1]`"的 off-by-one 错误，入口处强制按期号升序排序（防御数据源"最新一期在前"的倒序陷阱）
- 三个基线策略：随机基准（种子随机，不看历史）、热号（近50期频率最高）、冷号（遗漏期数最长）
- 独立的理论基准层：红球 33 选 6 的理论期望值 1.0909，不混在"随机策略"里
- 回测模式下完全不用裸的 `Math.random()`——随机策略用「期号+策略名」做种子的伪随机数，保证可复现
- 蒙特卡洛随机分布（5000 次独立模拟）+ 分位数，界面上优先展示分位数而不是 p 值
- 分层指标：均命中、95% 置信区间、蓝球命中率、极端事件次数（≥4/≥5/6红）、命中分布
- 近似资金曲线（明确标注为非精算估算，仅用于示意"长期负期望"）
- 每个策略的排行榜条目都同时给出数字和"能不能算有效"的判断，不因为数字好看就含糊过去

## 目录结构

```
lottery-lab/
├── data/
│   ├── ssq_source.json   # 原始抓取数据（未清洗）
│   ├── ssq.json          # 清洗后的标准格式数据（按期号升序）
│   ├── leaderboard.json  # 排行榜（回测产出）
│   └── report.json       # 完整报告数据（回测产出，前端页面据此生成）
├── src/
│   ├── rng.js                  # 种子伪随机数生成器
│   ├── strategies.js           # 随机 / 热号 / 冷号 / 我的策略(加权) 四个策略
│   ├── my-strategy-client.js   # "我的策略"滑块的浏览器端等价实现（V1 新增，会被内联进 index.html）
│   ├── backtest.js             # Walk-Forward 引擎 + 奖级判定 + 统计 + 蒙特卡洛
│   ├── svg-charts.js           # 构建期生成静态 SVG 图表（零运行时依赖）
│   ├── build.js                # 跑回测，产出 data/leaderboard.json、data/report.json
│   └── build-site.js           # 读取 report.json，生成 public/index.html（含"我的策略"交互）
├── scripts/
│   └── prepare-data.js    # 原始数据 → 标准格式
├── index.html              # 与 public/index.html 内容相同，方便直接部署到仓库根目录（见下方部署说明）
└── public/
    └── index.html         # 最终页面（自包含，双击即可打开，无需服务器/网络）
```

## 如何重新运行

需要 Node.js（开发时用的是 v22）。

```bash
node scripts/prepare-data.js   # 清洗原始数据 -> data/ssq.json
node src/build.js              # 跑回测 + 蒙特卡洛 -> data/leaderboard.json, data/report.json
node src/build-site.js         # 生成 public/index.html
```

三步跑完后直接打开 `public/index.html` 即可，不需要任何服务器或网络连接——所有数据和图表在构建期就已经算好并写死在页面里。以后接入新一期开奖数据，重新跑这三步就会得到一份新的、可复现的排行榜。

**关于盲测集边界的重要提醒**：`src/build.js` 里的 `VALIDATION_START_PERIOD`（26045）和 `BLIND_TEST_START_PERIOD`（26075）是这一版**手动写死**的常量。以后新增开奖数据、重新跑 `node src/build.js` 时，**不要**把这两个常量改成"当前数据的百分之多少"重新算一遍——那样会让盲测集随数据增长不断后移，变成一个名不副实的"最近窗口"。正确做法是让这两个常量保持不动，新增的期数会自动累积进盲测集（从当前 30 期慢慢变多）。只有在未来某个版本里**有意识地**决定"重新封存一批更大的盲测集"时，才应该修改这两个常量，并且要在这份 README 和发布记录里明确写清楚原因。

## 如何部署（三选一，都是免费的静态托管）

项目现在的产物是**一个自包含的 `index.html` 文件**（所有数据、图表、"我的策略"交互全部写死在文件里），部署本质上就是"把这一个文件放到一个能提供 HTTPS 访问的地方"，不需要数据库、不需要服务器常驻进程。三种方式按推荐程度排序：

### 方式一：Cloudflare Pages（方案里指定的目标平台，推荐）

**A. 不用 Git，直接拖拽上传（最快，几分钟搞定）**

1. 打开 https://dash.cloudflare.com/ → 左侧菜单选择 **Workers 和 Pages** → **创建应用程序** → **Pages** 标签页 → **上传资源**。
2. 给项目起个名字（比如 `lottery-lab`），点击继续。
3. 把 `public/` 文件夹**里面的内容**（也就是那个 `index.html`）拖进上传框——注意是上传 `public` 文件夹里的文件，不是上传整个项目压缩包。
4. 点击部署，等几十秒。Cloudflare 会给你一个形如 `https://lottery-lab-xxx.pages.dev` 的网址，直接能访问。
5. 以后每次改完代码、重新跑完三步构建脚本，回到这个项目页面，用同样的方式再上传一次 `public/index.html` 就能更新（会覆盖旧版本，Cloudflare 自动保留历史版本，出问题可以一键回滚）。

**B. 连 GitHub 仓库，自动部署（适合你打算长期维护、以后接 GitHub Actions 自动化的话）**

1. 先把整个项目推到一个 GitHub 仓库（见下方"顺手学一下 Git/GitHub"）。
2. Cloudflare Pages → 创建应用程序 → Pages → **连接到 Git**，选中你的仓库。
3. 构建配置填：
   - **构建命令**：`node scripts/prepare-data.js && node src/build.js && node src/build-site.js`
   - **构建输出目录**：`public`
4. 保存后，以后每次 `git push`，Cloudflare 都会自动重新跑这三步构建脚本、自动发布——这正是方案里"V1.5 自动化管道"想要的效果的前半段（后半段是让 GitHub Actions 自动抓新数据后自动 push，这部分还没做）。

### 方式二：GitHub Pages（如果你已经有 GitHub 账号，不想额外注册 Cloudflare）

1. 把项目推到一个 GitHub 仓库（比如仓库名 `lottery-lab`）。
2. 仓库设置 → **Settings** → **Pages**。
3. **Source** 选择 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`——这也是为什么项目根目录也放了一份和 `public/index.html` 内容相同的 `index.html`（GitHub Pages 的 root 模式只认根目录的 `index.html`，认不到 `public/` 子目录，除非你把目录改成 `/docs` 并把内容放进 `docs/`）。
4. 保存后一两分钟，访问 `https://<你的用户名>.github.io/lottery-lab/` 即可。
5. 以后重新构建后，记得**同时更新根目录的 `index.html` 和 `public/index.html`**（内容应保持一致），再 `git push`。

### 方式三：本地直接打开，不部署（临时看看效果）

不需要任何账号、任何网络，直接双击 `public/index.html` 用浏览器打开就行——"我的策略"滑块也能正常工作，因为所有计算都在浏览器本地完成。缺点是别人没法通过链接访问，只适合你自己验证效果。

### 顺手学一下：怎么把项目推到 GitHub（如果你还没用过 Git）

如果你还没安装 Git 和建过 GitHub 仓库，最简单的路径：

1. 去 https://github.com/new 建一个新仓库（比如叫 `lottery-lab`），不用勾选"添加 README"（本地已经有了）。
2. 在项目根目录下打开终端，依次执行：
   ```bash
   git init
   git add .
   git commit -m "V1: 我的策略权重滑块"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/lottery-lab.git
   git push -u origin main
   ```
3. 之后每次改完代码、重新跑完三步构建脚本，只需要：
   ```bash
   git add .
   git commit -m "描述这次改了什么"
   git push
   ```
   如果用的是方式一的 B 选项或方式二，push 之后会自动触发重新部署，不需要再手动做别的事。

### 关于自定义域名

Cloudflare Pages 和 GitHub Pages 都支持免费绑定自己的域名（如果你有的话）：Cloudflare Pages 在项目的 **自定义域** 里添加即可；GitHub Pages 在仓库 Settings → Pages → **Custom domain** 里添加，并按提示在你的域名服务商那边加一条 CNAME 记录。两者都会自动帮你签发免费的 HTTPS 证书，不需要额外操作。
